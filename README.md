# Metamorph — reproduction package

Metamorph treats replacing a vector database's embedding model as an **online,
budget-metered operation** instead of an offline re-embed and index rebuild.
One budget unit is one document re-embedded with the new encoder, and every
consumer of the new encoder draws from that single meter. Four mechanisms
cooperate:

- **Dual-space serving with calibrated fusion.** Queries are answered
  throughout the migration. Migrated documents carry exact new-space scores;
  unmigrated documents are scored by fusing their exact old-space score with a
  cross-space adapter score, calibrated per query on that query's
  already-migrated candidates.
- **Prioritized re-embedding.** Decayed traffic, query hardness and adapter
  disagreement decide which documents are re-embedded next.
- **Online certification.** Cost-capped sampling rounds bound the agreement
  between current serving and the fully migrated system with an anytime-valid
  betting confidence sequence, so re-embedding can stop early on a valid signal.
- **Warm-start index construction.** The new IVF / kNN-graph index is seeded
  from the old index's structure.

This package contains the implementation, the unit tests, every data-preparation
and experiment script, all result files with their provenance, and the figures
generated from them.

## Reference environment

All results were produced on one Apple M3 Ultra workstation (arm64, 32 cores,
512 GB RAM, no discrete GPU; macOS 26.5.2) with Python 3.12.13. Encoder
inference runs on the integrated accelerator through PyTorch MPS when available
and on CPU otherwise; all retrieval and experiment code runs on CPU (NumPy,
hnswlib, FAISS). Wall-clock numbers depend on the machine, and embeddings
computed on another device can differ in the last digits.

## Setup

```bash
python3.12 -m venv .venv
./.venv/bin/pip install -r requirements.txt     # exact versions used for the results
./.venv/bin/pip install -e . --no-deps
```

Alternatively, `pip install -e '.[models,experiments,dev]'` installs the same
packages without pinning. Encoders and datasets are downloaded from Hugging
Face and the BEIR host on first use and cached.

## 1. Check the installation (about 1–2 minutes)

```bash
./.venv/bin/python -m pytest src/tests -q        # 82 tests, synthetic data only
```

The suite covers the anytime validity of the confidence sequence, the
certifier's bias correction and pooling, a randomized soundness check of the
per-query certificate, and adversarial interleavings of scheduler batches and
queries against the migration invariants (exactly-once serving, monotonicity,
budget conservation, legal phase transitions).

A first end-to-end run on a 1,000-document corpus takes a few minutes. Experiments
write into `results/` and replace a shipped file of the same name, so keep a copy
of the shipped results to compare against:

```bash
cp -r results results_shipped
./.venv/bin/python experiments/prepare_data.py --dataset scifact --pair minilm-e5 --scale smoke
./.venv/bin/python experiments/exp1_migration_timeline.py --dataset scifact --pair minilm-e5 --scale smoke --seeds 42
```

## 2. Prepare the data

Every experiment reads a prepared bundle under `data/` holding both encoders'
document and query embeddings and the relevance judgments. The runs in
`results/` need the following bundles.

| Corpus | Documents | Encoder pairs | Command |
|---|---|---|---|
| scifact | 5,183 | minilm-e5, minilm-gte, albert-e5, minilm-e5base, minilm-e5large | `prepare_data.py --dataset scifact --pair <pair> --scale small` (and `--scale smoke` for minilm-e5) |
| nfcorpus | 3,633 | minilm-e5 | `prepare_data.py --dataset nfcorpus --pair minilm-e5 --scale small` |
| fiqa | 57,638 | minilm-e5, minilm-gte, minilm-e5large | `prepare_data.py --dataset fiqa --pair <pair> --scale full` |
| Quora | 522,931 | minilm-e5 | `prepare_large.py --dataset quora --pair minilm-e5 --tag xl` |
| MS MARCO passages | 8,841,823 | minilm-e5 | `prepare_large.py --dataset msmarco --pair minilm-e5 --tag xxl` |
| AG-News, DBpedia-14, Emotion; fiqa and the 1M MS MARCO rung with MPNet | 120,000 / 560,000 / 15,956 | see exp10 | `prepare_drift.py` (see the exp10 part below) |

Encoder pairs (old → new): **minilm-e5** all-MiniLM-L6-v2 → e5-small-v2
(384 → 384); **minilm-gte** → gte-small (384 → 384); **albert-e5**
paraphrase-albert-small-v2 → e5-small-v2 (768 → 384); **minilm-e5base** →
e5-base-v2 (384 → 768); **minilm-e5large** → e5-large-v2 (384 → 1024, 335M
parameters). exp10 adds all-mpnet-base-v2 (768d) as a destination.

Scales cap the corpus size: `smoke` (1k), `small` (6k), `full` (60k), and the
memory-mapped bundles `xl` (1M) and `xxl` (10M). Scale-ladder rungs are
seeded sub-samples of one bundle that keep every judged document, so corpus
size varies while dataset, encoder pair and workload stay fixed.

Disk and time on the reference machine: everything under `data/` (extracted
corpora, embedding caches, prepared bundles and cached indexes) takes about
55 GB, about 40 GB of it for MS MARCO. Embedding all of MS MARCO with both
encoders took 10,797 s; `prepare_large.py` encodes in checkpointed chunks and resumes
after an interruption, and `truncate_bundle.py` turns a partial encode into a
valid smaller bundle.

## 3. Run the experiments

`results/RUNS.md` lists, for every result file, the exact command that
produced it (reconstructed from the arguments recorded in its sidecar). Every
script writes its CSVs, each with a `.meta.json` sidecar, into `results/`,
replacing a shipped file of the same name (`--out` redirects only a script's
main CSV). Runs are seeded, and each sidecar records the seeds used.

| Script | What it measures | Result files |
|---|---|---|
| `exp1_migration_timeline.py` | Quality against budget for every method: full re-embed and swap, random order, static adapter, offline popularity prior, oracle traffic, Metamorph; `--verify N` adds query-time verification to any method | `exp1_timeline_*` |
| `exp2_scheduler_ablation.py` | Scheduler signals and annealing variants | `exp2_sched_*` |
| `exp3_adapter_ablation.py` | Adapter families, seed-fraction sweep, query modes; the adapter alone and inside the engine | `exp3_adapters_*` |
| `exp4_warmstart_index.py` | Warm against cold NN-descent and k-means (distance computations) | `exp4_warmstart_*` |
| `exp4b_faiss_warmstart.py` | Warm-started FAISS IVF-Flat: build time and recall across corpus sizes up to 4M | `exp4b_faiss_*` |
| `exp5_certification.py` | Certifier bias, coverage and fire timing; pool depth, bound family, target metric | `exp5_cert_*`, `exp5_certwin_*` |
| `exp6_latency.py` | Per-query latency by stage; `--compaction` compares old-index compaction policies | `exp6_latency_*` |
| `exp7_encoder_cost.py` | Encoder throughput, batch-size effect, and a migration with the live encoder against re-embed-and-swap | `exp7_throughput_*`, `exp7_projection_*`, `exp7_live_*` |
| `exp8_margin_bound.py` | The per-query certificate against the truth; monotonicity of serving quality | `exp8_margin_*`, `exp8_monotonicity_*` |
| `exp9_scale_ladder.py` | Prioritization gain against corpus size on the Quora and MS MARCO ladders | `exp9_ladder_*` |
| `exp10_driftadapter_repro.py` | Drift-Adapter under its published protocol, and factor checks | `exp10_driftadapter_*` |

Run times recorded in the result files (sums over methods, seeds and rungs;
several of the longer runs shared the machine with other jobs): exp1 takes
1.5–9 min per small-corpus command and 11–27 min per fiqa command; the exp9
ladders take about 1.6 h on Quora and 15 h on MS MARCO for all rungs and
seeds; exp10 commands take 0.4–47 min. Encoder throughput (exp7) was measured
on an otherwise idle machine. FAISS build times (exp4b) and latencies (exp6)
were measured on a shared machine and are compared as ratios; the cold and warm
builds of each size ran back to back in the same process.

Frequently used output columns: `budget_frac` (fraction of the corpus
re-embedded, all reasons), `recall@10_vs_dest` (agreement with the fully
migrated system's top-10, held-out queries), `recall@10_vs_dest_wl` (the same
on the live workload), `ndcg@10` and `mrr@10` (against relevance judgments),
`cert_lb_pooled` (the anytime certification lower bound), and `cost_*`
(budget spent by reason).

## 4. Drift-Adapter reproduction (exp10)

exp10 reproduces Drift-Adapter (Vejendla, EMNLP 2025) under every setting its
publication states: new-model queries mapped into the old space by orthogonal
Procrustes, a rank-64 affine map or a residual MLP (the last two with diagonal
scaling), trained with MSE and AdamW on 20,000 random database documents,
searched in a FAISS HNSW index over the old vectors (M = 32,
efConstruction = 200, efSearch = 50), and scored by Recall@10 against the new
model's exhaustive nearest neighbours relative to the re-embedded system
(ARR), over 5 runs. It uses Drift-Adapter's own datasets and model pair
(AG-News, DBpedia-14 and Emotion with all-MiniLM-L6-v2 → all-mpnet-base-v2),
and adds sanity checks (identity and rotated upgrades), convergence and
hyperparameter-grid training recipes, a sample-size sweep, the corpus-side
direction, other destinations, a lenient metric, task-level metrics, and two
retrieval corpora (fiqa and a 1M-passage MS MARCO sub-sample).

```bash
# corpora and encoders (Hugging Face); fiqa and MS MARCO reuse the bundles prepared above
./.venv/bin/python experiments/prepare_drift.py --datasets emotion agnews dbpedia14 --models minilm mpnet e5s gtes
./.venv/bin/python experiments/prepare_drift.py --datasets emotion agnews dbpedia14 --labels-only
./.venv/bin/python experiments/prepare_drift.py --datasets fiqa msmarco1m --models mpnet
# e.g. the three Drift-Adapter benchmarks with its published recipe (5 runs)
./.venv/bin/python experiments/exp10_driftadapter_repro.py --settings agnews:minilm:mpnet dbpedia14:minilm:mpnet emotion:minilm:mpnet --tag mytag
# tables of all shipped exp10 results
./.venv/bin/python experiments/summarize_exp10.py
```

`experiments/DRIFT_ADAPTER_REPRODUCTION.md` lists each stated setting next to
what was run, the settings the publication leaves open or states
inconsistently, and the choice made for each. PyTorch and FAISS each bundle
their own OpenMP runtime on macOS and abort when both are loaded in one
process, so exp10 trains adapters in a spawned PyTorch-only worker
(`drift_train.py`), applies them in NumPy, and checks the NumPy inference
against the PyTorch forward pass on every fit.

Main result (`results/exp10_summary.md`; ARR, 5 runs, largest run-to-run
standard deviation 0.006):

| Benchmark (MiniLM → MPNet) | Un-upgraded model | OP | LA | MLP | Published OP / LA / MLP |
|---|---|---|---|---|---|
| AG-News | 0.546 | 0.500 | 0.308 | 0.481 | 0.974 / 0.983 / 0.992 |
| DBpedia-14 | 0.363 | 0.245 | 0.103 | 0.221 | 0.968 / 0.979 / 0.990 |
| Emotion | 0.306 | 0.390 | 0.263 | 0.359 | 0.953 / 0.967 / 0.984 |
| fiqa | 0.397 | 0.423 | 0.270 | 0.391 | – |
| MS MARCO (1M) | 0.545 | 0.411 | 0.156 | 0.384 | – |

## 5. Figures

```bash
./.venv/bin/python experiments/make_figures.py   # -> results/figures/*.pdf, results/figures/data/*.dat
```

Every figure is drawn from the CSVs in `results/`. Ladder figures pool all
comparable rung files and skip any rung whose recorded workload differs from
the ladder's 4,000 queries. `exp1_stack_fiqa_minilm-e5_full.pdf` shows held-out
NDCG@10 and live-workload agreement for fiqa MiniLM → E5 on one budget axis.
The series plotted in the fiqa timelines, the scale ladders and the latency
comparison are also written to `results/figures/data/` as whitespace-separated
tables (one row per point, `nan` for a missing point), so they can be re-plotted
with any tool:

| File | Columns |
|---|---|
| `exp1_ndcg_fiqa_minilm-e5_full.dat`, `exp1_wl_fiqa_minilm-e5_full.dat` | budget `b`; per method the 5-seed mean and the min/max band (`<method>`, `<method>_lo`, `<method>_hi`); the old- and new-model levels; the static adapter's frozen level and the budget where it froze |
| `exp9_gap_quora.dat`, `exp9_gap_msmarco.dat` | corpus size `n`; Metamorph's agreement gap at half budget over random order and over the offline prior; the hot-set fraction |
| `exp6_compaction_{masked,compacting}_*.dat` | budget `b`; p50 and p99 per-query latency (ms), without verification |

## Expected variation

Checked on the reference machine: re-preparing scifact from a fresh download
reproduced the stored embeddings bit for bit, and re-running the shipped
scifact MiniLM → E5 timeline command (all methods, 5 seeds) reproduced the
random-order baseline exactly. Methods whose trajectories depend on the
scheduler and the certifier (Metamorph, the offline prior, oracle traffic) are
not bit-for-bit deterministic even with a fixed seed: repeating a seed changed
budget accounting by up to about 1% of the corpus and agreement by up to about
0.02 at a given step. Their 5-seed means moved by at most a quarter of the
seed-to-seed standard deviation; for example, Metamorph's budget to 95%
workload agreement was 0.944 in the shipped file and 0.939 in the re-run, with
a seed standard deviation of 0.020. Compare re-runs against the shipped files
at the level of seed means.

## Provenance

Each result file's sidecar records the exact arguments, the engine and
certifier configuration, the actual corpus and query counts, and the platform.
`results/PROVENANCE.md` records the machine, the configuration history (which
runs were repeated when certifier defaults changed, since certification
reveals feed back into the migration trajectory), the exact corpus sizes, and
the seed completion of the scale ladders. New-model embeddings are normally
read through a budget-metered oracle, so a migration timeline replays in
minutes with exact cost accounting; exp7 reruns the engine with the live
encoder and confirms that the live vectors reproduce the oracle exactly
(maximum cosine gap 0).
